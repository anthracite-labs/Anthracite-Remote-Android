# Full-repository audit — remediation record

Audit target: PR #8 head `1dad773`. Everything below is at `be88d27` and later.
Each finding is marked **fixed**, **partly fixed**, or **open**, with the test that
covers it or the reason it is not closed. Nothing here is claimed as verified on a
real host, device, cluster or GitHub installation.

## Critical

| ID | Status | Change and evidence |
| --- | --- | --- |
| C-01 iOS hand-written keyscan spoke an invalid KEX | **fixed** | The scanner no longer implements SSH. `HostKeyScanner` runs a real `NIOSSHHandler` handshake and stops at the host-key delegate: the delegate records the parsed key and then *fails* the validation promise, so no credential is ever offered. Version exchange, KEXINIT, algorithm negotiation and packet padding are now NIOSSH's. The OpenSSH string and fingerprint come from NIOSSH's own serializer. Evidence: `HostKeyConversionTests` (round-trip through `NIOSSHPublicKey`, the fixture's `ssh-keygen` fingerprint, and the pinned-vs-presented comparison). **Not proven:** a live OpenSSH server handshake — there is none in CI, so "it works against OpenSSH" remains untested; only "the handshake is a real one" is now true by construction. |
| C-02 `kubectl apply` adopted an existing unmanaged object | **fixed** | Creation is `kubectl create -f -`; `AlreadyExists` is reported as "left untouched" (exit 64) and the manifest is never retried as an update. The RBAC check for creation is `can-i create` (also M-08). Evidence: `DeployGuardTest` — "creation is create-only and never adopts an existing object", "creation checks create permission, not patch", plus the positive path. **Not proven:** a live API server; the semantics of `create` are kubectl's, not re-implemented here. |

## High

| ID | Status | Change and evidence |
| --- | --- | --- |
| H-01 environment file could truncate a pre-existing file or follow a symlink | **fixed** | The file name carries a per-plan 64-bit token, so it can only be this plan's file. The command refuses a symlinked or group/other-accessible `~/.anthracite/deploy`, then writes under `set -C` (noclobber → `O_CREAT\|O_EXCL`, which fails on an existing file *and* on a symlink) rather than `>`. Removal runs in `finally`, including after a failed write. Evidence: `DeployContainerIdentityTest` (private directory, noclobber, per-plan token, removed on failure, removed after start, secret only on stdin). **Residual:** `set -C` is not `O_NOFOLLOW` in every shell; the check-before-write window and the directory TOCTOU are narrowed, not eliminated, when another local process is racing inside the user's own home. |
| H-02 iOS `readFile` returned a truncated prefix as a whole file | **fixed** | Reads continue until `STATUS(EOF)`; reaching the cap without EOF throws `tooLarge`; a zero-length DATA reply is a protocol violation rather than an assumed EOF. Evidence: `TransferSafetyTests` covers framing; the EOF loop itself needs a server and is **not** covered. |
| H-03 iOS SFTP could wait forever | **fixed** | Every request has a 30 s deadline, the **handshake** now has its own 20 s deadline, a malformed frame length is fatal and fails every waiter, cancellation resumes the caller instead of waiting for the deadline, and `close()` releases everyone. Evidence: `SFTPClientStateTests` drives the real client through a scripted peer — silent server, delayed reply, wrong version, impossible frame, disconnect, cancellation, `close()` with a request in flight. See P0-2 below, which also removed the re-entrant handshake that could suspend a caller forever. **Not proven:** a live OpenSSH `sftp-server`. |
| H-04 scan error could be lost before the waiter attached | **fixed** | The capture delegate stores the terminal `Result` under a lock before resuming, and a late waiter is resumed from that stored result. The timeout also resolves through the same path. This code replaced the scanner in C-01. |
| H-05 check-then-mutate identity race on delete/rollback | **fixed for delete, narrowed for rollback** | The earlier note that `DeleteOptions.preconditions { uid }` is unavailable through `kubectl delete` was wrong. `kubectl delete` supports `--raw` with a body taken from stdin (`staging/src/k8s.io/kubectl/pkg/cmd/delete/delete.go` → `rawhttp.RawDelete`, `staging/src/k8s.io/kubectl/pkg/rawhttp/raw.go` at v1.31.0), and the API server evaluates `preconditions.uid` inside the DELETE itself. The delete is now such a request, so a replaced object cannot be deleted and the shell UID comparison is only an explanation for the user; the unconditional `kubectl delete NAME` is gone from the code. Evidence: `DeployGuardTest` (one delete, the exact argv, no `--ignore-not-found` anywhere) and `DeployKubernetesDeleteShellTest`, which executes the generated command under `/bin/sh` with a stand-in `kubectl` and asserts the argv and the document on stdin, and that a refusal propagates as a non-zero status. **Rollback** (`kubectl rollout undo`) has no equivalent precondition: it keeps the narrowed window and the plan's warning says which of the two is enforced by the cluster. |
| H-06 Android SFTP upload cannot guarantee no-overwrite | **open — guarantee refused** | Checked at the library level: JSch 2.28.8 declares `SSH_FXF_EXCL` privately and never sends it (`sendOPEN` is called only with `WRITE\|CREAT\|TRUNC` or `WRITE\|CREAT`), so there is no exclusive create to use, and SFTP v3 `RENAME` replaces. The upload therefore keeps its two refusal points (before the write and again immediately before the rename) and the app no longer implies a guarantee it cannot keep: the KDoc, `docs/support-matrix.md` and this table say "not guaranteed". A file created in the microseconds between the last check and the rename can still be replaced. |
| H-07 iOS tmux attachment had no identity | **fixed** | `AppModel.attach(tmuxSession:)` re-reads the listing and requires name **and** id to match before opening the tab, and stores the verified session on the tab. `detach` is offered only for such a tab and closes the channel; the hard-coded Ctrl-B D write is gone. Evidence: identity rules are unit tested in `TmuxPresenceTests`; the attachment flow itself is UI-level and **not** covered by a test. |
| H-08 unknown host id fell back to the active host | **fixed** | `HostPicker`/`resolveHostOrFinish` separate "explicit id did not resolve" from "no id given": five screens (Bootstrap, Deploy, Files, Git, Workspace) now stop with a message instead of acting on the active host. Evidence: `HostSelectionTest`. |
| H-09 container removal checked name+label, then removed by name | **fixed** | Creation records the runtime's immutable id; removal re-reads the id for that name, requires it to equal the recorded id **and** the ownership label, then removes by full id. Evidence: `DeployContainerIdentityTest` — renamed container, missing label, no recorded id, unreadable inspect, and the positive case. |

## Corrective pass — 2026-10-23 (second assignment)

Both reported defects were reproduced before anything was changed: the P0-1
pattern under dash and bash, and the P0-2 handshake against a scripted peer.

| ID | Status | Change and evidence |
| --- | --- | --- |
| P0-1 the environment-file guard never matched | **fixed** | `DeployPlans.envFileCommand()` compared a ten-character `ls -ld` mode string with the eleven-character pattern `d????------`, which cannot match. Every container deployment with environment variables exited 73 before starting a container. Replaced with `stat`-based checks (GNU `-c`, BSD `-f` fallback): the directory must not be a link, must exist, must be owned by the connecting user and must be exactly 0700; an existing target is refused without being opened; `set -C` keeps the create exclusive; a write that fails half-way removes its own partial file (new exit 74); after writing, the file is re-checked as a regular 0600 file. The app now sends the removal only when this run wrote the file, so a refusal can never delete somebody else's file, and the removal still runs in `finally`. Evidence: `DeployEnvFileShellTest` executes the generated command under `/bin/sh`, dash and bash in a disposable HOME — 0700 accepted; 0750/0755/0777, symlinked directory, symlinked target, pre-existing file and a `ulimit -f` partial write refused or cleaned up; two plans writing at once neither collide nor delete each other; the secret never appears in argv or in any command. |
| P0-2 iOS SFTP could suspend a caller forever | **fixed** | (a) `start()` was re-entrant: two concurrent callers both sent INIT and the second overwrote `pending[0]`, so the first was never resumed. (b) The version exchange had no deadline. (c) A malformed VERSION left the client free to retry on a desynchronised stream. (d) Cancellation never reached `pending`, so a cancelled request waited for its timeout — and with `Task.sleep` cancelled, `expire` never ran at all. The client now has one state (idle, one shared handshake task, open, failed), one completion path (`take(id)` removes the entry and returns the continuation, so it is resumed exactly once), a bounded handshake, terminal failure that closes the channel, `close()` releasing every waiter, and cancellation resuming the caller at once. Evidence: `SFTPClientStateTests` drives the real client through a scripted in-memory peer: one INIT for concurrent first callers, silent server, version 4 failing closed, disconnect and an impossible frame, delayed and out-of-order replies, a late reply after a timeout, cancellation, `close()` with a request in flight, an upload/download round trip and a refused write leaving no temporary file. **Not proven:** a live `sftp-server`. |
| P1-1 k8s delete race | **fixed** | See H-05. The API server enforces the reviewed UID inside the delete; the shell comparison is advisory and is not described as atomic anywhere. |
| P1-2 Android upload no-overwrite | **guarantee refused** | See H-06. No atomic primitive exists in JSch or SFTP v3, so the app documents the residual instead of claiming the guarantee. |

Still open after this pass, in the order the audit ranks them: H-06 (above),
M-03 (unbounded iOS terminal buffers — fixing it without dropping bytes means
applying backpressure to the channel, a design change rather than a cap), M-04
(iOS GitHub pagination), M-06 (XcodeGen not pinned by checksum, no
`Package.resolved`), M-09 (Kubernetes identity still session-scoped), M-11 (no
production lifecycle evidence, not closable here), M-12 (SFTP recursive delete
vs. a swapped symlink), L-04 and L-05.
